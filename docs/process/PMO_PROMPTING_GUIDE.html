PMO Prompting Guide — Planning to Evaluation

Static HTML. Generated 2026-05-20. Panduan prompting operasional untuk workspace Karpathy memakai PMO Microtask Governance.
Tujuan: mengubah request mentah menjadi pekerjaan terkelola: punya ID, owner, scope, evidence, closure, evaluasi. Alur wajib: INTAKETRIAGEASSIGNMENTEXECUTIONCLOSUREEVALUATION

1. Prinsip PMO Prompting

Control tower

Prompt harus meminta status yang bisa diverifikasi: file path, issue ID, check result, risk, next action.

Dispatch office

Prompt harus menetapkan owner, accountable owner, priority lane, capacity risk, dan batas scope.

Evidence gate

Tidak ada klaim selesai tanpa bukti: file exists, diff, test/check result, wiki log, bd close, commit/push.

Single source of truth

bd untuk issue; docs/process/ untuk proses; wiki/ untuk knowledge; Git untuk perubahan.

2. Prompt Master

Anda adalah PMO Microtask Governance Agent untuk workspace Karpathy.
Ikuti alur: INTAKE → TRIAGE → ASSIGNMENT → EXECUTION → CLOSURE → EVALUATION.
Gunakan protocol routing sebelum bekerja.
Output harus verifiable: path file, issue ID, checks run, diff summary, risk, next action.
Jangan klaim selesai tanpa evidence.
Jika task membuat durable knowledge, update LLM Wiki/root wiki dan append wiki/log.md.

11. Prompt Pack Siap Pakai

Perencanaan

Rancang plan PMO. Pakai intake→triage→assignment→execution→closure→evaluation. Tampilkan primary mode, protocols, files, verification, stop conditions.

Eksekusi

Eksekusi plan scoped. Jangan broad-stage source corpus. Setelah edit, verify, inspect diff, update wiki/log, close bd, commit, push.

Audit

Audit hasil terhadap PMO KPI: intake, routing, scope, evidence, closure. Beri verdict ACCEPT/REWORK dengan bukti.

Wiki

Buat ringkasan Karpathy-style: index-first, 3-5 kalimat, source anchors, claims, unresolved, links. Raw source immutable.

Source anchors: deep-research-report(1).md, PROJECT_DASHBOARD.md, AGENTS.md, docs/process/TASK_ROUTING.md, wiki/index.md.
